# Agent 热词都在说什么

> MCP、Memory、Skill 和 Subagent

上一节里，我们已经得到了一个 Agent。

它能看到上下文，能选择工具，能看到工具返回的结果，也能在任务完成时结束。

那么，经常听到的 MCP、Memory、Skill 和 Subagent 又是什么？

它们看起来是许多新东西，其实大多只是在改变三件事：

> 大模型眼前有什么、它能做什么，以及它怎样继续工作。

## 改变它眼前的东西

**Memory** 就是把过去发生的事保存起来，等需要时再取出来。

Memory 不会神奇地一直留在大模型的脑子里。只有被取出来、放进这一次的上下文，它才能被大模型看见。

**Skill** 更像一份事先写好的工作说明书。比如，处理照片时应该注意什么，写新闻稿时应该先核对哪些信息。做到这类任务时，对应的说明书才会被摆到大模型眼前。有些 Skill 还会附带工具或现成材料。

**RAG** 做的事也很直接：先从一大堆资料里找到相关的部分，再把它放进上下文。

如果把上下文想成工作桌，Memory 是旁边的笔记本，Skill 是书架上的说明书，RAG 则是帮它把有用的几页找出来。只有摆到桌上的内容，才是当下的上下文。

## 改变它能做的事

**MCP** 是一套共同的接法。

不同的软件可以用这套接法，告诉 Agent 自己提供哪些工具和资料。这样，Agent 不需要为每一个软件重新学一种连接方式。

所以，MCP 本身不是一个工具。但从 Agent 眼里看，通过 MCP 接进来的“查天气”“读文件”“发消息”，仍然是一个个工具。

**WebMCP** 是让网页也能这样做。一个购物网站可以把“搜索商品”“加入购物车”提供给 Agent。对 Agent 来说，它们还是工具；“Web”只是说，这些工具来自当前打开的网页。

**Subagent** 是被当作工具使用的另一个 Agent。

主 Agent 可以说：“你去调查这件事，再把结果交给我。”对主 Agent 来说，这只是一次调用；但在里面，Subagent 也有自己的上下文、工具和工作过程。

## 改变它怎样继续

**Goal 模式**既不是新的上下文，也不是新工具。它是 Agent 外面的一种控制方式：只要目标还没有完成，就让 Agent 继续工作；直到目标被判定为已完成，或者实在无法继续。

“目标是什么”会被放在上下文里。“还要不要继续”则是 Goal 模式在外面控制的事。

它适合需要很长时间的任务，但不是 Agent 必须具备的东西。没有 Goal 模式，上一节的文件整理 Agent 仍然是一个完整的 Agent。

## 把新名词放回原位

以后再听到一个 Agent 新名词，可以先问：

- 它是在把新东西放到大模型眼前吗？
- 它是在给 Agent 增加新工具吗？
- 它是在决定 Agent 怎样继续或结束吗？

大多数看起来复杂的名词，都可以放回这张简单的地图里。
