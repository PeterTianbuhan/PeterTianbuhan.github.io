当界面不再固定

我梦见一块白色的大屏幕，中间是 Grok Bot 的头像，下面一个输入框，我说话，它就在屏幕上给我组织页面。醒来以后我接着想：如果把软件拆成资源、能力和界面，App 只是它们被提前绑好的样子，有了 Agent，这个绑定就可以在使用中重新来。

昨天晚上我做了个梦，梦见一块纯白的大屏幕，中间只有一个 Grok Bot 的头像，下面是输入框。我在里面输入，它回应我，同时一直在这块屏幕上给我组织页面。

梦里就这么多。醒来以后，我接着想这块屏幕会怎么工作。

这块屏幕大概是这样的

比如我说「把刚才的梦记下来，我想写篇文章」，屏幕上先出现一小段记录。我接着往下说，文章的结构就在旁边慢慢长出来，想清楚的部分留在原地，互相打架的想法被放到一起。Agent 一边听，一边用声音回我。

我说「把这两种说法放一起」，屏幕就变成左右对比；我说「这段我想自己写」，旁边才出现一个编辑器。要查资料，资料就出现在当前内容旁边，不用我再去打开另一个 App、找到对应的页面。

我也可以直接动手。眼前东西堆太多了，手一挥关掉；过一会儿想起其中一页有用，握一下拳，刚才的变化就撤回了。这些动作不是在精确地拖坐标，更像是在告诉它我的意思。

下次再写文章，这块屏幕还记得我喜欢怎么对比内容，哪些事我想自己决定，什么时候它应该少说两句。

现在的 Agent 还做不到这些。它基本还住在聊天框里，我发一段字，它回一段字。它也能生成图片、图表、网页、能点的组件，但最后还是被塞进一条往下滚的消息流里。

我觉得要从聊天框走到那块屏幕，光换个输入方式不够，软件本身得换一种组织方式。

把软件拆成三样东西

我试着把能交互的软件拆成三样东西：Resource、Capability 和 Interface。

Resource 是系统里有的东西，一份代码、一篇文章、一封邮件、一笔订单，或者一段正在跑的状态。

Capability 是系统能做的事，保存、读取、搜索、运行、发送、比较、购买、撤销。

Interface 是人怎么看到和操作这些东西，编辑器、表格、时间轴、地图、表单、播放器、语音。同一份 Resource 可以有不同的 Interface，同一个 Capability 也可以从不同的 Interface 去调用。

这些 Interface 放在一起的地方，我叫它 Scene。Scene 就是一块画布，放着当前需要的 Interface，记着它们在哪、多大、谁挨着谁。梦里那块白屏幕就是一个 Scene。

App 是提前绑好的

现在的软件，是把这三样东西提前绑成一个个 App。

Spotify 把音乐和歌单、搜索播放收藏这些能力、播放器和推荐页绑在一起；日历把事件、创建和提醒、月视图周视图绑在一起。以前这么做很合理，软件不懂人想干什么，开发者只能提前猜用户会怎么用，准备好一套页面和路径。所以人用软件，其实是在别人提前修好的路里，找一条离自己目的最近的。

但真实的事情不按 App 的边界来。比如准备明天的考试，要课程资料、错题、日历、学习记录，要搜索、排时间、提醒、模拟测验。今天得在文档、日历、题库、笔记和聊天工具之间来回切。

有了 Agent，这件事就可以不一样。如果系统能懂我现在想干什么，也能调底层的能力，这三样东西就不用一直保持原来的绑法，Agent 可以围着当前这件事，把它们重新组织进一个 Scene。准备考试就可以有一个只为这场考试存在的 Scene，考完了资料还在，这个 Scene 也能存下来，下次接着用。

我不觉得 App 会马上消失，这更像是我想要的一种可能：App 不用永远是这三样东西的固定边界。

Scene 和 Interface

Scene 决定此刻哪些东西同时出现在眼前、怎么摆，Interface 是 Scene 里具体的组件。

一段代码可以先在阅读器里，开始改的时候多出一个编辑器，要比较的时候再出现一个左右对比。某个组件从画布上拿掉了，代码还在，变的只是它现在用什么方式出现。

Interface 也不用锁死在某个 App 里。只要对得上，同一个表格、时间轴、对比器可以在很多地方用。开发者还是要给出推荐的 Interface，他们对自己领域怎么交互最有判断，但这只是起点，最后 Scene 里出现什么、怎么组合，人和 Agent 可以接着定。

每个人的界面都不一样

固定的界面要求所有人走差不多的页面和菜单，Scene 可以围着眼前这个人来组织。

这不只是换个主题、调个字号。有人对比代码喜欢原版放左边，有人想先看差异；有人希望 Agent 少问、先做，有人希望它一有歧义就停下来。就算是同一个人，写东西、学习和付钱的时候，希望 Agent 离自己的距离也不一样。

人说的话、做的调整、停顿，都是信号，但不是每个信号都应该让 Agent 改主意。什么时候接着做，什么时候停下来问，很难给所有人写成同一条规则。人和 Agent 最后会形成自己的相处边界，这个边界每个人不一样，也会随着用得久了慢慢变。

所以我觉得值得存下来的不只是某一次的布局，还有这些偏好：什么东西喜欢用什么组件看，哪些 Interface 经常放一起，Agent 该多主动，哪些事可以先做再说，哪些必须先问。这些可以跨任务，甚至跨领域一直用下去。

怎么做出来

我觉得关键不是让模型直接生成页面，而是让 Resource、Capability 和 Interface 都不再被某个页面或者 App 独占。

Agent 本身不用重做，它原来那些工具还在，用来读写 Resource、调 Capability。在这之外再给它加一组 Scene 工具，用来把 Interface 放上画布、移动、缩放、拿掉，还有看看人眼前现在是什么样。Scene 工具不会让它多出任何权限，把一个 Resource 放进某个 Interface，不代表它就能读这个 Resource。

权限也不用是一堵永远挡在前面的墙。现在人已经可以把自己电脑差不多全部的操作权交给 Agent，很多能力长期授权就行，不用每步都确认。要守住的主要是事实：Agent 可以操作文件、跑程序、摆界面，但不能把失败的结果写成成功，不能为了好看去改真实发生的事情。

至于从哪开始，我觉得 Web 可以是第一代 Scene 的运行环境。现在的网页先当成一个个 Interface 放进来，再慢慢拆开、重新组合。

最后

聊天框是我们最早学会和 Agent 相处的方式，但我不觉得它会是最后一种。

我想要的不是 Agent 更熟练地替我去点今天那些软件的按钮，而是软件自己能围着我想做的事改变形状，用得越久，越像我自己的软件。
